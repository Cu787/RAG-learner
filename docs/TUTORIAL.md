# 教程：从零理解并搭建一个 RAG

本教程按"数据 → 加载 → 切块 → 向量化 → 检索 → 生成"的顺序，
带你走一遍 RAG 的每一环。阅读时建议**打开对应源码对照着看**。

> 目标：读完你能自己回答——"为什么需要切块？""相似度到底在算什么？"
> "为什么要给出处？"这些 RAG 的核心问题。

---

## 0. 先建立直觉

想象你是客服，桌上堆着一摞资料。有人问："我们年假几天？"

你会：
1. **翻资料**，找出讲"年假"的那一段（**检索**）；
2. **照着那段话**回答顾客（**生成**）。

RAG 就是把这两步交给程序：
- 检索 = "翻资料"，靠**向量相似度**自动完成；
- 生成 = "照着答"，可以交给大模型，也可以只是一段程序。

关键洞察：**检索的准确程度，决定了最终答案的上限。**
所以本项目默认的"生成器"很朴素（只列出命中片段），
目的是让你能清楚地看到——**检索到底找对没有**。

---

## 1. 数据：知识从哪来

RAG 的"知识"就是你的文件。项目里放在 `data/`：

```
data/company_handbook.md   # 员工手册
data/product_guide.md      # 产品说明
data/faq.txt               # 常见问题
```

`loaders.py` 把每个文件读成一个 `Document(text, source)`：
- `text` 是正文；
- `source` 是文件名，用来在答案里做**引用**（"答案来自哪篇文档"）。

---

## 2. 切块：为什么不能整篇拿去检索

假设你问"年假几天？"，而整篇手册有 3000 字。
如果拿整篇去比对，这篇手册里"报销、考勤、年假"全都混在一起，
相似度会被**稀释**，反而找不到重点。

所以先切成小块（几百字以内），**每块是一个独立的检索单位**。
切得太碎会丢上下文，切得太大又不够聚焦——`chunk_size` 就是调节这个平衡的旋钮。

`chunking.py` 的策略：
- 以"行"为单位累加，保留 Markdown 的标题/列表结构；
- 接近 `chunk_size` 就"切一刀"；
- 相邻块重叠 `chunk_overlap` 个字符，防止一句话被拦腰斩断。

用 `python main.py --show-chunks` 能直接看到切块结果——**这是调试 RAG 的第一步**。

---

## 3. 向量化：让计算机"算得懂"文本

计算机只会算数字，所以要把文本变成**向量**（一串数字）。

### 最朴素的想法：词袋
给词表里每个词分配一个位置，文本里出现几次就在对应位置记几。
但这样有个问题："的""是"这种**到处都有的词**权重也很大，很干扰。

### TF-IDF 的改进
- **TF**（词频）：某个词在这段文本里出现得多 = 这段文本越"关于"这个词；
- **IDF**（逆文档频率）：某个词在**整个资料库**里越稀有 = 越有区分度。

两者相乘：常见的词权重低，稀有的词权重高。这就是 TF-IDF。

代码在 `embeddings.py`：
- `fit(corpus)`：统计整个资料库，算出每个词的 IDF，建好词表；
- `encode(text)`：把一段文本变成向量，并做 **L2 归一化**（让向量长度=1）。

### 中文怎么分词？
中文词之间没有空格。项目用「**单字 + 相邻双字(bigram)**」：
"年假天数" → `年, 假, 天, 数` + `年假, 假天, 天数`。
不用装 jieba 也能有不错的效果，是个工程折中。

---

## 4. 检索：余弦相似度

我们想知道"问题向量"和"每个块向量"有多像。
用**余弦相似度**——它只看两个向量的**方向**是否一致，不看长度：

```
cos(a, b) = (a · b) / (|a| * |b|)
```

- 方向相同 → 0° → cos = 1（最相似）
- 方向垂直 → 90° → cos = 0（不相关）

因为向量已经 L2 归一化（长度为 1），所以这里**点积就等于余弦相似度**。
`vector_store.py` 的 `search()` 就是：算出所有分数 → 排序 → 取 Top-K。

---

## 5. 生成：把资料变成答案

拿到 Top-K 片段后，把它们和问题拼成**提示词**，交给生成器。

`generator.py` 里的提示词模板（也是真实 RAG 常用的写法）：

```
你是一个严谨的问答助手。请仅根据下面的参考资料回答用户问题。
如果参考资料中没有答案，就明确回答"根据现有资料无法回答"，不要编造。

参考资料：
[1] (来源：company_handbook.md) ...
[2] ...

用户问题：公司年假有几天？

请用简洁的中文回答，并在句末标注用到的资料编号，例如 [1]、[2]。
```

要点：
- **要求"只根据资料回答"** → 降低幻觉；
- **要求"没有就说没有"** → 避免瞎编；
- **要求"标注编号"** → 方便溯源。

默认的 `ExtractiveGenerator` 不做语言生成，只是把命中片段整理出来；
想体验真正的生成，装好 Ollama 后用 `python main.py --generator ollama`。

---

## 6. 串起来：pipeline.py 的一次完整数据流

以问题 **"公司年假有几天？"** 为例：

```
1. 加载：3 个文件 → 3 个 Document
2. 切块：每篇切几块，共 8 个块
3. 向量化：TF-IDF.fit(8 个块) 学词表 → 每个块 encode 成 958 维向量
4. 建索引：8 个向量存进 VectorStore
5. 提问：把问题 encode 成向量
6. 检索：与 8 个块算余弦相似度 → 取 Top-3
        （实测命中 company_handbook.md，相似度约 0.41）
7. 生成：把 Top-3 交给生成器 → 输出答案
```

这正是 `python main.py -q "公司年假有几天？"` 背后发生的事。

---

## 7. 如何判断你做得好不好（评估）

- **检索对不对**：看输出的"命中片段"里有没有正确答案。这是第一优先级。
- **调参**：`top_k` 太小可能漏掉答案，太大可能带入噪声。
- **换向量模型**：词匹配不行就上语义模型（`sentence-transformer`）。
- **改切块**：答案被切断？调大 `chunk_overlap`；段落太杂？调小 `chunk_size`。

## 8. 常见坑

| 现象 | 可能原因 | 对策 |
| --- | --- | --- |
| 完全找不到相关内容 | 词表里没有对应的词 | 换语义向量 / 补数据 |
| 答案被截断 | 切块把句子切开了 | 调大 `chunk_overlap` |
| 命中一堆无关内容 | `top_k` 太大 / 阈值太低 | 调小 `top_k`、提高 `min_score` |
| 中文效果差 | TF-IDF 只认词 | 上 `sentence-transformer` |

## 9. 继续深入的方向

1. **更好的向量**：`sentence-transformers`、BGE、OpenAI embedding；
2. **专业向量库**：FAISS、Chroma、Qdrant、Milvus（支持海量数据与持久化）；
3. **更强检索**：混合检索（关键词 + 向量）、重排序（rerank）、HyDE、多路召回；
4. **更好生成**：接入本地/在线 LLM、流式输出、多轮对话记忆；
5. **工程化**：索引持久化、增量更新、评估集与自动化测试。
